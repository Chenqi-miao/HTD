# stage2 评估结果 (2026/8/25)

## 背景

**stage2 = 单帧 s1 前置 + exp2 时序网络 级联**。

- **s1**(`exp2_s1_att_grouped` / SingleFrameGrouped,用户自己设计的单帧模型):逐帧把位置 DC 修正干净
- **stage2 s15** = `s1 → Stage2Net`(`exp2_s15_stage2`)
- **stage2 s31** = `s1 → exp2_net`(`exp2_s31_s1exp2`)

设计逻辑:位置误差是主要误差,且注意力对整体平移(DC 偏移)不敏感 → 先单帧把位置修好,再让时序网络在干净输入上专注修运动。

## 评估口径

- 数据:`SeqHandTest`(服务器 pkl 管线),**2000 窗**,相机空间 masked
- 指标:MPJPE / MPJVE / MPJAE / PA-MPJPE / corr_v / corr_a + 输入 jerk 三桶(低/中/高)的 输入/模型 MPJPE
- 统一推理协议(原生逐窗,非重叠,无滑动平均污染)
- **输入(input)基线**:同一套 mask 下同时评估 输入 vs GT 与 模型 vs GT。表格首行是输入,后续每行与之对比即模型的绝对修正量
- 对比组:exp1(DSTFormer depth=2,只吃位置)、原版 exp2 纯 Transformer(15/31 帧)、stage2 级联(15/31 帧)

## 关键结论

1. **stage2 s31 全面最强**:每一项指标(位置/运动/PA/抖动分桶)都赢原版 s31。高抖动桶 **20.22 → 11.96,几乎减半**,之前一直困扰的"两级分化/高抖动桶拖垮"被大幅缓解。

2. **stage2 抹平了长窗的位置劣势**:原版 s31(10.75)明显差于原版 s15(9.42),但 stage2 s31(9.08)反超 stage2 s15(9.41)。说明 s1 前置把位置修好后,长窗的动力学优势才在干净输入上兑现。这与"位置误差是主要误差、需单独修位置"的既有洞察吻合。

3. **s1 的纯增量可直接度量**:原版 vs stage2 的差(s31 = 1.67mm)就是 s1 前置的贡献,是现成的消融证据,答辩可直接用。

4. **stage2 s15 的效果主要在运动**:MPJPE 9.42 → 9.41 几乎不动,但 corr_v/corr_a 大幅提升。15 帧窗口下 s1 未带来位置收益(位置修正已饱和),但有轻微代价:低/中抖动桶(7.46/8.88)略差于原版(7.21/8.70)。stage2 s31 无此代价,所有桶都赢。

5. **对比口径说明**:所有相对对比都在同一 2000 窗协议下,是公平的;全量(142930 窗)非必需(历史"全量教训"是训练预算问题,不适用评估窗口)。绝对数字如要对外报告,建议标注抽样口径。

6. **口径注(重要)**:本报告数字均为**逐点平均**口径(标准 MPJPE 定义,每个有效帧-关节等权)。历史训练日志基准(原版 s31 = 12.77、LRU+best = 12.18)是**窗口平均**口径(每窗等权),两者**不可直接比较**。原版 s31 分桶 7.80/10.28/20.22 与训练日志完全一致,已反推窗口口径下原版 s31 ≈ 12.77。窗口口径下 stage2 优势更大(因高抖动桶改善最明显,而窗口平均放大高抖动桶权重)。

7. **exp1 定位 = 位置好、运动差**:exp1 是 DSTFormer depth=2 + 只吃 3 维位置(无速度/加速度输入)。MPJPE 9.35(s15)全场最好,但 corr_v/corr_a 0.630/0.207 全场最弱,MPJVE/MPJAE 全部最差,高抖动桶 20.04 未改善。exp1(位置好/运动差)、exp2(位置中/运动中)、stage2(位置好/运动好)三档并排,直接印证"位置误差与运动误差可分离":空间网络专修位置、时序网络+动力学输入修运动。

8. **s1 单独修位置 ≈ 9.85(训练日志)**:训练日志 s1 单独 Test MPJPE 最佳 9.85(Epoch 5,窗口口径)。**本次补同口径逐点评估(31帧窗)**:s1 单独 MPJPE **9.91**、PA 8.64、corr_a 0.345、高桶 **12.92**。链条(31帧窗逐点):输入 13.66 → s1 9.91(**-27.5%**,位置/高桶大头由 s1 修)→ stage2_s31 9.08(相对 s1 再 **-8.4%**,corr_a 0.345→0.629,运动由时序网精修)。"位置交给 s1、运动交给 exp2"分工坐实。(注:9.85 是窗口口径,9.91/9.08 是逐点口径,数字不可直接比)

9. **输入基线 & 修正量(跨窗长修正)**:输入基线**依赖窗长** —— 15帧窗 13.62(高桶19.96)、31帧窗 13.66(高桶20.72),必须**同窗长对比**。同窗长(31帧窗)下:stage2_s31 相对输入 13.66 修到 9.08(**-33.5%**),高桶 20.72→11.96(**-42.3%**);s1 单独就把高桶修到 12.92(-37.6%)。而无 s1 的 31帧窗模型高桶仅 exp1_s31 +3.3% / exp2_s31 +2.4%、PA +7~9%,stage2_s31 高桶 +42.3% / PA +26.1% —— **s1 前置把高抖动桶与结构(PA)修复放大一个量级**。⚠️ 此前版本"无 s1 模型高桶负优化(-1.3%)"是**跨窗长假象**(用15帧窗输入对比31帧窗模型),已废弃。

## 评估脚本修复 (eval_all_metrics.py 原本没跑完的 3 个 bug)

1. **corr 累加广播错误**:`vp`/`ap_` 含坐标维 `[F-1,J,3]`,mask `vm`/`am` 是 `[F-1,J]`,直接相乘崩溃;补 `[..., None]` 广播。
2. **s31"原版"加载错 checkpoint**:原来加载 `best.pth`(LRU 混合版,结构是 LRUTransformer,与纯 Transformer `net.py` 不匹配),`strict=False` 导致权重未对齐、输出 143mm 垃圾;改为 `best_orig_full.pth`(原版纯 Transformer,验证 strict 加载 0 missing/unexpected)。修复后分桶 7.80/10.28/20.22 与原版日志 Epoch25 的 7.805/10.280/20.220 几乎完全一致,确认加载正确。
3. **stage2 s15 输入 key 传错**:`Stage2Net.forward` 吃 `inputs['p_s1']`,脚本传成 `joint_xyz` 导致 KeyError;`exp2_net.py`(s31 stage2)是原版 exp2 结构、吃 `joint_xyz`,按模型分别传对应 key。
